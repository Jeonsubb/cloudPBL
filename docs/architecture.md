# PortPulse AWS 아키텍처

## 1. 전체 방향

PortPulse는 단순 뉴스 요약 챗봇이 아니라, 사용자의 실제 선적 데이터와 시장 데이터를 결합해 **개별 선적 단위의 리스크**를 판단하는 서비스입니다.

핵심 흐름은 다음과 같습니다.

```text
사용자 웹 접속
→ 로그인
→ 선적/견적/엑셀 원본 업로드
→ 문서 파싱·정규화
→ 회사 데이터 저장
→ 시장 데이터 매일 수집
→ 리스크 점수 계산
→ Bedrock 설명/챗봇/리포트 생성
→ 위험 알림 발송
```

## 2. AWS 서비스별 담당 역할

| 영역 | AWS 서비스 | 역할 |
| --- | --- | --- |
| 도메인 | Route 53 | 서비스 도메인 연결 |
| 웹 전달 | CloudFront | 정적 웹 화면을 빠르게 전달 |
| 정적 웹 | S3 | React 빌드 결과물 저장 |
| 인증 | Cognito | 로그인, 사용자 인증, 회사별 접근 제어 |
| API | API Gateway | 프론트엔드 요청을 Lambda로 전달 |
| 백엔드 | Lambda | 선적 등록, 업로드 URL 발급, 리스크 계산, 챗봇 호출, 알림 발송 |
| 사용자 파일 | S3 | 견적서, 엑셀, 부킹 확인서 원본 저장 |
| 문서 분석 | Lambda / Textract | 업로드 문서에서 운임, 유효기간, ETD/ETA 등 추출 |
| 시장 데이터 수집 | EventBridge Scheduler | 매일 아침 데이터 수집 Lambda 실행 |
| 시장 데이터 원천 | KCCI, SCFI, ECOS, 관세청, 뉴스 | 운임, 환율, 수출입, 이벤트 데이터 |
| 데이터 허브 | Aurora PostgreSQL | 회사 데이터, 시장 데이터, 리스크 결과 저장 |
| AI | Amazon Bedrock | 챗봇, 리포트, 위험 원인 설명 |
| AI 도구 연결 | Bedrock Agent Action Group | Bedrock이 Lambda 도구를 호출해 DB/시장 데이터 조회 |
| 알림 | Lambda + Telegram/Kakao | 위험 선적 알림 발송 |
| 운영 | CloudWatch | 로그, 에러, 실행 모니터링 |

## 3. 데이터 플로우

### 3.1 사용자 데이터 처리

1. 사용자가 웹에서 로그인합니다.
2. 사용자가 선적 일정 또는 견적서/엑셀 파일을 등록합니다.
3. 백엔드 Lambda가 S3 업로드 URL을 발급합니다.
4. 원본 파일은 S3에 저장됩니다.
5. S3 업로드 이벤트가 문서 파싱 Lambda를 실행합니다.
6. Lambda가 파일에서 선적명, 출발지, 도착지, 운임, 견적 유효기간, ETD, ETA 등을 추출합니다.
7. 정규화된 결과를 Aurora PostgreSQL에 저장합니다.

### 3.2 시장 데이터 수집

1. EventBridge Scheduler가 매일 아침 수집 Lambda를 실행합니다.
2. Lambda가 KCCI, SCFI, 환율, 수출입 통계, 뉴스 데이터를 수집합니다.
3. 원문은 S3에 저장하고, 요약/수치 데이터는 Aurora PostgreSQL에 저장합니다.
4. 뉴스와 리포트는 Bedrock이 참고할 수 있도록 요약 또는 RAG 형태로 연결합니다.

### 3.3 리스크 판단 및 AI 설명

1. 사용자가 대시보드에서 선적을 조회합니다.
2. Lambda가 Aurora에서 회사 선적 데이터와 시장 데이터를 가져옵니다.
3. 룰 기반 리스크 엔진이 위험 점수를 계산합니다.
4. Bedrock이 “왜 위험한지”, “지금 무엇을 해야 하는지”를 자연어로 설명합니다.
5. 위험도가 높으면 알림 Lambda가 텔레그램/카카오톡/이메일로 알림을 발송합니다.

## 4. MVP에서 단순화할 부분

4~6일 개발기간을 고려하면 아래처럼 구현 범위를 조절합니다.

| 항목 | MVP 구현 | 발표/확장 설명 |
| --- | --- | --- |
| 로그인 | Cognito 또는 임시 사용자 토큰 | 회사별 데이터 분리 |
| 데이터베이스 | PostgreSQL 또는 Aurora 호환 구조 | 실제 배포 시 Aurora PostgreSQL |
| 알림 | 텔레그램 우선 | 카카오톡은 확장 |
| AI Agent | Bedrock 단일 호출 + Lambda 도구 | 향후 멀티에이전트 확장 |
| 문서 파싱 | 엑셀/텍스트 PDF 우선 | 스캔본은 Textract 확장 |

## 5. 개선 포인트

- API Gateway가 큰 파일을 직접 받지 않도록 S3 Presigned URL 업로드 방식을 사용합니다.
- AI가 점수를 마음대로 만들지 않도록 리스크 점수는 Lambda의 룰 엔진이 계산합니다.
- Bedrock은 점수 산출자가 아니라 “근거 설명자”로 사용합니다.
- 사용자 파일에는 견적·거래 정보가 포함될 수 있으므로 S3 암호화, IAM 최소권한, Cognito 인증을 적용합니다.
- CloudWatch 로그를 남겨 발표 시 “운영 가능한 클라우드 서비스”임을 보여줍니다.
