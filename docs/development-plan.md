# 4~6일 MVP 개발계획

## 개발 목표

최종 데모에서 사용자가 다음 흐름을 직접 확인할 수 있게 만드는 것이 목표입니다.

```text
로그인
→ 선적 정보 등록
→ 견적서/엑셀 업로드
→ 리스크 점수 확인
→ AI 설명/챗봇 질의응답
→ 위험 알림 확인
```

## Day 1 — 프로젝트 골격과 화면 흐름

- GitHub 저장소 구조 정리
- 프론트엔드 기본 화면 구성
- 백엔드 Lambda/API 골격 작성
- 데이터 모델 초안 확정
- 샘플 선적 데이터 작성

완료 기준:

- 웹에서 선적 목록/상세 더미 데이터를 볼 수 있음
- 백엔드 기본 API 응답 확인

## Day 2 — 사용자 입력과 파일 업로드

- 선적 등록 폼 구현
- S3 Presigned URL 업로드 API 구현
- 엑셀/견적서 샘플 업로드 흐름 구현
- 업로드 메타데이터 저장

완료 기준:

- 사용자가 파일을 선택해 업로드할 수 있음
- 파일 정보가 DB 또는 임시 저장소에 남음

## Day 3 — 문서 파싱과 리스크 룰

- 엑셀 샘플 파싱
- 견적 유효기간, ETD/ETA, 운임 정보 추출
- 룰 기반 리스크 점수 계산
- 리스크 등급 UI 표시

완료 기준:

- 샘플 선적이 낮음/주의/위험 등급으로 계산됨

## Day 4 — 시장 데이터와 AI 설명

- KCCI/SCFI/환율/뉴스 샘플 수집 또는 더미 데이터 구성
- EventBridge 수집 Lambda 구조 작성
- Bedrock 리스크 설명 프롬프트 작성
- 챗봇 UI와 Bedrock API 연결

완료 기준:

- “왜 위험한가?” 질문에 Bedrock이 근거 기반 설명을 생성함

## Day 5 — 알림과 발표 시나리오

- 텔레그램 또는 이메일 알림 연동
- 호르무즈/홍해/운임 급등 데모 시나리오 구성
- 리포트 생성 화면 구성
- 발표용 데모 데이터 고정

완료 기준:

- 위험 선적 발생 시 알림 메시지가 전송됨
- 발표자가 3분 내 데모 가능

## Day 6 — QA와 발표자료 정리

- 오류 처리
- 화면 문구 정리
- AWS 아키텍처 설명 보완
- 역할분담 및 구현 범위 정리
- 최종 발표 리허설

완료 기준:

- 데모 시나리오가 처음부터 끝까지 끊기지 않음
