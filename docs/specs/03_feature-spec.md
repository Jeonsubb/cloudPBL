# PortPulse 기능 명세

PortPulse는 부산/경남권 중소 수출기업이 해상운임 변동 리스크를 예산과 납기 기준으로 해석하고, 적절한 부킹 타이밍을 판단하도록 돕는 웹 서비스다.

서비스 경험은 바로 로그인으로 시작하지 않는다. 사용자는 먼저 랜딩 화면에서 PortPulse가 어떤 데이터를 보고 어떤 방식으로 판단하는지 확인한 뒤, 실제 선적 건을 등록해 개인화 분석으로 넘어간다.

---

## 1. 전체 기능 구조

```text
랜딩/시장 대시보드
→ 서비스 소개 및 공개 데이터 프리뷰
→ 데모 보기 또는 로그인
→ 선적 정보 등록
→ 견적서/엑셀 업로드
→ 시장 데이터와 매칭
→ 부킹 타이밍 분석
→ AI 근거 설명
→ 매일 아침 브리핑
→ 위험 선적 Push 알림
```

## 3. 화면별 기능 명세

## 3-1. 랜딩/시장 대시보드

### 목적

로그인 전에 PortPulse가 다루는 핵심 데이터와 판단 방식을 보여준다. 단순 홍보 페이지가 아니라, 실제 웹서비스처럼 보이는 공개형 시장 대시보드 역할을 한다.

### 핵심 메시지

```text
PortPulse는 부산발 해상운임, 환율, 뉴스 이벤트를 결합해
내 선적 건의 부킹 타이밍을 매일 먼저 알려주는 서비스입니다.
```

### 주요 구성

| 영역 | 내용 |
| --- | --- |
| 상단 헤더 | PortPulse 로고, 서비스 소개, 데이터, 데모 보기, 로그인 버튼 |
| 히어로 영역 | “부킹 타이밍을 감이 아니라 데이터로 판단” 메시지 |
| 공개 시장 지표 카드 | KCCI, SCFI, 원/달러 환율, 주요 뉴스 이벤트 |
| 항로별 운임 프리뷰 | 부산 → 미주서안, 부산 → 북유럽, 부산 → 동남아 등 |
| 샘플 부킹 추천 카드 | 예산 대비 초과 가능성, 추천 행동 예시 |
| 데이터 출처 영역 | KCCI, SCFI, ECOS, 관세청, 뉴스 |
| CTA | “내 선적 분석 시작하기”, “데모 대시보드 보기” |

### 공개 데이터 카드 예시

| 카드 | 예시 값 | 설명 |
| --- | --- | --- |
| KCCI 부산발 미주서안 | 2,340p / 전주 대비 +7.8% | 메인 운임 변동 신호 |
| SCFI | 2,506p / 4주 평균 상승 | 글로벌 보조 지표 |
| 원/달러 환율 | 1,380원 / 전일 대비 -0.4% | 원화 비용 부담 |
| 주요 이벤트 | 항만 혼잡, 홍해 우회, 유가 변동 | 운임 영향 뉴스 |

### 샘플 부킹 추천 카드

```text
부산 → 미주서안 / 8월 3주차 선적 예시

예산 $2,800/FEU 대비 예상 운임 +18%
월 4 FEU 기준 약 $2,016 초과 가능성

추천:
2주 내 부킹 확정 또는 일부 물량 선적 시점 앞당기기 검토
```

### 사용자 액션

| 액션 | 결과 |
| --- | --- |
| 데모 보기 클릭 | 샘플 회사 기준 메인 대시보드 진입 |
| 내 선적 분석 시작 클릭 | 로그인/회사 선택 화면으로 이동 |
| 데이터 출처 클릭 | 각 데이터의 역할 설명 표시 |
| 항로 변경 | 공개 시장 지표 카드 값 변경 |

### MVP 구현 기준

- 실제 API 연동 전에는 샘플 데이터로 표시한다.
- 랜딩 화면은 로그인 없이 접근 가능하다.
- “마케팅 페이지”보다 “서비스 미리보기”에 가깝게 구성한다.
- 공개 화면에서는 회사별 민감 데이터는 절대 표시하지 않는다.

## 3-2. 로그인/회사 선택

### 목적

사용자와 회사를 식별하고, 회사별 선적 데이터가 섞이지 않도록 분리한다.

### 주요 기능

| 기능 | 설명 |
| --- | --- |
| 이메일 로그인 | Cognito 기반 로그인 |
| 데모 회사 선택 | 발표용 샘플 회사로 바로 진입 |
| 회사 정보 조회 | 회사명, 업종, 기본 항로 확인 |
| 사용자 권한 구분 | admin/member 구분 |

### MVP 구현 기준

- 실제 Cognito 연동 전에는 데모 로그인 버튼으로 대체 가능하다.
- 발표 시에는 “부산 수출기업 데모” 회사로 바로 진입할 수 있게 한다.

## 3-3. 메인 대시보드

### 목적

사용자가 로그인 후 가장 먼저 보는 화면이다. 내 선적 건 중 위험한 항목과 오늘의 시장 변화를 한눈에 보여준다.

### 주요 구성

| 영역 | 내용 |
| --- | --- |
| 오늘의 부킹 타이밍 | 가장 위험한 선적 건의 추천 행동 |
| 리스크 점수 카드 | HIGH/MEDIUM/LOW와 점수 |
| 시장 펄스 | KCCI, SCFI, 환율, 뉴스 이벤트 |
| 진행 중 선적 목록 | 선적별 위험도와 상태 |
| AI 브리핑 | 오늘의 시장/선적 요약 |
| Push 상태 | 텔레그램/카카오톡/이메일 설정 여부 |

### 선적 목록 필드

| 필드 | 예시 |
| --- | --- |
| 선적명 | 자동차 부품 1차 |
| 항로 | 부산 → LA |
| 선적 예정 | 2026년 8월 3주차 |
| 물량 | 4 FEU |
| 예산단가 | $2,800/FEU |
| 위험도 | HIGH |
| 추천 | 2주 내 부킹 확정 |

### 사용자 액션

| 액션 | 결과 |
| --- | --- |
| 선적 클릭 | 분석 결과 상세 화면으로 이동 |
| 선적 등록 클릭 | 선적 등록 화면으로 이동 |
| AI에게 질문 클릭 | 챗봇 패널 열림 |
| 알림 발송 클릭 | 설정된 Push 채널로 현재 경보 발송 |

## 3-4. 선적 등록

### 목적

개인화 분석에 필요한 선적 기준값을 입력받는다. 사용자가 즉시 아는 값만 입력하도록 설계한다.

### 입력 항목

| 항목 | 필수 | 예시 | 역할 |
| --- | --- | --- | --- |
| 선적명 | 필수 | 자동차 부품 1차 | 선적 식별 |
| 출발 항만 | 필수 | 부산 | 항로 매칭 |
| 도착 권역/항만 | 필수 | 미주서안 / LA | KCCI/SCFI 매칭 |
| 선적 예정 시기 | 필수 | 2026년 8월 3주차 | 예측 지평 |
| Incoterms | 필수 | CIF / CFR / FOB | 운임 부담 주체 |
| 물량 | 필수 | 4 FEU | 초과 비용 환산 |
| 기준 예산단가 | 선택 | $2,800/FEU | 예산 초과 판단 |
| 품목 | 선택 | 자동차 부품 | 성수기/뉴스 해석 보조 |
| 납기일 | 선택 | 2026-09-05 | 납기 리스크 판단 |

### 유효성 검사

| 조건 | 처리 |
| --- | --- |
| 출발/도착 항로 누락 | 저장 차단 |
| 선적 예정 시기 누락 | 저장 차단 |
| 물량이 숫자가 아님 | 입력 오류 표시 |
| 예산단가 미입력 | 예산 초과 분석은 비활성화 |
| Incoterms가 FOB | 운임 부담 여부 안내 표시 |

## 3-5. 파일 업로드/추출 확인

### 목적

포워더 견적서나 엑셀 파일을 업로드해 실제 운임, 견적 유효기간, ETD/ETA를 추출한다.

### 지원 파일

| 파일 | MVP 지원 | 설명 |
| --- | --- | --- |
| xlsx | 예 | 가장 먼저 지원 |
| csv | 예 | 단순 견적 데이터 |
| pdf 텍스트 | 선택 | 가능하면 지원 |
| 스캔 PDF/이미지 | 후순위 | Textract 확장 |

### 추출 항목

| 항목 | 예시 |
| --- | --- |
| 포워더명 | ABC Logistics |
| 기본 운임 | $2,950 |
| 부대비용 | $180 |
| 통화 | USD |
| 견적 유효기간 | 2026-07-20 |
| ETD | 2026-08-18 |
| ETA | 2026-09-02 |
| 원본 파일 경로 | S3 key |

### 사용자 액션

| 액션 | 결과 |
| --- | --- |
| 파일 선택 | S3 Presigned URL로 업로드 |
| 추출 결과 확인 | 파싱된 값 표시 |
| 값 수정 | 사용자가 잘못 추출된 값 보정 |
| 분석 실행 | 리스크 계산 시작 |

## 3-6. 분석 결과 상세

### 목적

특정 선적 건에 대해 왜 위험한지, 얼마가 초과될 수 있는지, 지금 어떤 행동을 해야 하는지 보여준다.

### 주요 구성

| 영역 | 내용 |
| --- | --- |
| 부킹 타이밍 추천 | 지금 부킹, 1~2주 대기, 물량 조정 등 |
| 리스크 점수 | 0~100점, LOW/MEDIUM/HIGH |
| 예산 초과 계산 | 단가 초과율, 총 초과 예상액 |
| 일정 리스크 | ETD/ETA, 납기 여유 |
| 시장 근거 | KCCI, SCFI, 환율, 뉴스 |
| 추천 행동 | 포워더 확인, 견적 연장, 선복 확보 등 |
| AI 설명 | 쉬운 자연어 설명 |

### 리스크 결과 예시

```json
{
  "riskScore": 82,
  "riskLevel": "HIGH",
  "bookingRecommendation": "BOOK_WITHIN_2_WEEKS",
  "budgetOverrunRate": 18,
  "estimatedExtraCost": 2016,
  "reasons": [
    "KCCI 부산-미주서안 항로가 전주 대비 7.8% 상승했습니다.",
    "예산 $2,800/FEU 대비 예상 운임이 약 18% 높습니다.",
    "8월 3주차 선적까지 남은 시간이 짧습니다."
  ],
  "recommendedActions": [
    "2주 내 부킹 확정을 검토하세요.",
    "포워더에게 선복 확보 가능 여부를 확인하세요.",
    "견적 유효기간 연장을 요청하세요."
  ]
}
```

### 추천 상태

| 상태 | 의미 |
| --- | --- |
| BOOK_NOW | 즉시 부킹 권고 |
| BOOK_WITHIN_2_WEEKS | 2주 내 부킹 확정 권고 |
| WATCH | 관찰 필요 |
| WAIT | 단기 대기 가능 |
| INSUFFICIENT_DATA | 판단 데이터 부족 |

## 3-7. AI 챗봇

### 목적

사용자가 리스크 결과와 시장 상황을 자연어로 질문할 수 있게 한다. Bedrock은 점수를 새로 만드는 것이 아니라, Lambda가 계산한 결과와 저장된 근거를 설명한다.

### 질문 예시

```text
부산-LA 8월 선적 지금 잡는 게 좋아?
왜 위험도가 HIGH야?
홍해 이슈가 미주서안에도 영향 있어?
예산을 $3,000으로 올리면 위험도가 낮아져?
포워더한테 뭐라고 물어봐야 해?
```

### 응답 원칙

| 원칙 | 설명 |
| --- | --- |
| 근거 기반 | 저장된 선적/시장 데이터만 사용 |
| 점수 생성 금지 | 리스크 점수는 룰 엔진 결과를 사용 |
| 출처 표시 | KCCI, SCFI, ECOS, 뉴스 등 표시 |
| 실무 행동 중심 | 사용자가 바로 할 수 있는 행동 제안 |
| 불확실성 표시 | 데이터가 부족하면 부족하다고 말함 |

## 3-8. 알림 설정

### 목적

사용자가 매일 아침 브리핑과 위험 선적 경보를 받을 채널과 기준을 설정한다.

### 알림 채널

| 채널 | MVP | 설명 |
| --- | --- | --- |
| 텔레그램 | 1순위 | 구현이 빠르고 발표 데모에 적합 |
| 이메일 | 2순위 | 리포트 발송용 |
| 카카오 알림톡 | 확장 | 승인/템플릿 절차 필요 |

### 알림 종류

| 종류 | 설명 |
| --- | --- |
| 매일 아침 브리핑 | 시장 데이터와 내 선적 요약 |
| 위험 선적 경보 | 특정 선적이 기준을 넘었을 때 발송 |
| 견적 유효기간 알림 | 유효기간 3일 이하 |
| 납기 임박 알림 | ETA와 납기일 여유 부족 |

### 설정 항목

| 항목 | 예시 |
| --- | --- |
| 브리핑 시간 | 매일 오전 9시 |
| 위험도 기준 | HIGH 이상 |
| 예산 초과 기준 | +10% 이상 |
| 초과 금액 기준 | $1,000 이상 |
| 알림 채널 | 텔레그램 ON, 이메일 ON |

## 4. 기능 우선순위

## 4-1. 1차 MVP 필수

| 기능 | 이유 |
| --- | --- |
| 랜딩/시장 대시보드 | 서비스 첫인상과 데이터 기반 느낌 제공 |
| 데모 회사 진입 | 발표 시 로그인 부담 제거 |
| 선적 등록 | 개인화 분석의 시작점 |
| 기준 예산단가/물량 입력 | PortPulse 차별점의 핵심 |

## 6. 화면 목업 제작 기준

화면 목업은 다음 순서로 만드는 것이 좋다.

1. 랜딩/시장 대시보드
2. 메인 대시보드
3. 선적 등록
4. 파일 업로드/추출 확인
5. 분석 결과 상세
6. AI 챗봇
7. 알림 설정

첫 화면은 로그인 화면이 아니라 랜딩/시장 대시보드다. 사용자는 로그인 전에도 PortPulse가 어떤 데이터를 보고 어떤 판단을 하는지 볼 수 있어야 한다.

## 7. MVP 데모 시나리오

```text
1. 사용자가 PortPulse 랜딩 화면에 접속한다.
2. 공개 시장 대시보드에서 KCCI, SCFI, 환율, 뉴스 이벤트를 확인한다.
3. "데모 보기"를 눌러 부산 수출기업 데모 계정으로 진입한다.
4. 자동차 부품 1차 선적 건을 확인한다.
5. 예산 $2,800/FEU, 월 4 FEU 기준 초과 비용을 확인한다.
6. PortPulse가 "2주 내 부킹 확정 권고"를 표시한다.
7. 사용자가 AI에게 "왜 지금 부킹해야 해?"라고 질문한다.
8. AI가 KCCI 상승, 예산 초과, 선적 예정 시기를 근거로 설명한다.
9. 사용자가 텔레그램 알림 발송을 누른다.
10. 위험 선적 경보 메시지가 발송된다.
```

이 시나리오가 끊기지 않으면 1차 MVP 데모는 성공으로 본다.
