# PortPulse 유저플로우

PortPulse의 유저플로우는 크게 3개로 나눈다.

1. 최초 등록 플로우
2. 매일 아침 브리핑 플로우
3. 위험 선적 발생 시 알림 플로우

이 3개 플로우가 합쳐져서 사용자는 "선적 정보를 한 번 등록하고, 이후에는 매일 부킹 타이밍 판단을 먼저 받는" 경험을 하게 된다.

---

## 1. 최초 등록 플로우

### 목적

사용자가 PortPulse에 회사와 선적 정보를 등록하고, 개인화된 부킹 타이밍 판단에 필요한 기준값을 설정한다.

### 사용자 상황

부산/경남권 중소 수출기업의 무역 또는 물류 담당자가 신규 수출 건을 준비하고 있다. 아직 운임이 확정되지 않았거나, 포워더 견적을 받은 직후이며, 지금 부킹을 걸어야 할지 조금 기다려야 할지 판단하고 싶다.

### 플로우

```text
서비스 접속
→ 로그인 또는 데모 회사 선택
→ 선적 건 등록
→ 항로 선택
→ 선적 예정 시기 입력
→ Incoterms 선택
→ 물량 입력
→ 기준 예산단가 입력
→ 견적서/엑셀 파일 업로드
→ 업로드 파일 파싱
→ 회사/선적 데이터 저장
→ 초기 리스크 분석
→ 대시보드에서 결과 확인
```

### 화면 단위

| 단계 | 화면 | 주요 액션 |
| --- | --- | --- |
| 1 | 로그인/회사 선택 | 회사별 데이터 분리 기준 생성 |
| 2 | 선적 등록 | 항로, 선적 예정일, Incoterms, 물량 입력 |
| 3 | 견적서 업로드 | 포워더 견적서 또는 엑셀 업로드 |
| 4 | 추출 확인 | 파싱된 운임, 유효기간, ETD/ETA 확인 |
| 5 | 초기 분석 결과 | 예산 초과 가능성, 납기 여유, 시장 리스크 확인 |

### 입력 데이터

| 항목 | 예시 | 역할 |
| --- | --- | --- |
| 회사 | 부산 수출기업 데모 | 회사별 데이터 분리 |
| 항로 | 부산 → 미주서안 | KCCI/SCFI 항로 매칭 |
| 선적 예정 시기 | 2026년 8월 3주차 | 예측 지평 설정 |
| Incoterms | CIF / CFR / FOB | 운임 부담 주체 판단 |
| 물량 | 월 4 FEU | 초과 비용 환산 |
| 기준 예산단가 | $2,800/FEU | 예산 초과 경보 기준 |
| 견적서 파일 | forwarder_quote.xlsx | 실제 견적 정보 추출 |

### 시스템 처리

```text
Frontend
→ API Gateway
→ Lambda
→ S3 Presigned URL 발급
→ 사용자가 S3에 파일 업로드
→ S3 이벤트로 파싱 Lambda 실행
→ 파일에서 운임/유효기간/ETD/ETA 추출
→ Aurora PostgreSQL 저장
→ 리스크 룰 엔진 실행
→ Bedrock이 결과 설명 생성
```

### 성공 상태

사용자는 대시보드에서 다음 정보를 확인할 수 있다.

- 등록한 선적 건
- 현재 리스크 점수
- 예산 초과 예상 금액
- 부킹 타이밍 추천
- 근거 데이터 출처
- AI 설명

### 실패/예외 상태

| 상황 | 처리 |
| --- | --- |
| 필수값 누락 | 해당 입력 항목 강조 후 저장 차단 |
| 파일 파싱 실패 | 수동 입력 화면 제공 |
| 항로 매칭 실패 | 가장 가까운 KCCI 항로 후보 제안 |
| 예산단가 미입력 | 예산 초과 판단은 생략하고 시장 리스크만 표시 |

## 2. 매일 아침 브리핑 플로우

### 목적

사용자가 매번 접속해서 시장 데이터를 조회하지 않아도, PortPulse가 매일 아침 시장 변화와 등록된 선적 건의 상태를 먼저 요약해준다.

### 사용자 상황

물류 담당자는 출근 후 여러 포워더와 메일/전화로 커뮤니케이션해야 한다. PortPulse는 매일 아침 먼저 오늘의 운임, 환율, 뉴스 이벤트, 내 선적의 주의점을 요약해준다.

### 플로우

```text
매일 아침 정해진 시간
→ EventBridge Scheduler 실행
→ 시장 데이터 수집 Lambda 실행
→ KCCI/SCFI/ECOS/관세청/뉴스 데이터 수집
→ 원문은 S3 저장
→ 정제 데이터는 Aurora 저장
→ 등록된 회사별 선적 건 조회
→ 선적별 리스크 재계산
→ Bedrock이 일일 브리핑 생성
→ 대시보드 업데이트
→ 텔레그램/카카오톡/이메일로 브리핑 발송
```

### 화면 단위

| 단계 | 화면/채널 | 주요 액션 |
| --- | --- | --- |
| 1 | 대시보드 | 오늘의 시장 펄스 확인 |
| 2 | 선적 목록 | 리스크 높은 선적 우선 확인 |
| 3 | AI 브리핑 | 자연어 요약 확인 |
| 4 | Push 채널 | 텔레그램/카카오톡 알림 수신 |

### 수집 데이터

| 데이터 | 역할 | 사용 방식 |
| --- | --- | --- |
| KCCI | 부산발 운임 메인 지표 | 항로별 단기 변동 판단 |
| SCFI | 글로벌 운임 보조 지표 | 장기/글로벌 추세 보완 |
| ECOS | 환율, 금리 | CIF 부담 및 원화 비용 해석 |
| 관세청 | 품목/물동량/성수기 보조 | 특정 품목 수요 신호 참고 |
| 뉴스 | 돌발 이벤트 | 홍해, 파업, 유가, 항만 혼잡 감지 |

### 브리핑 메시지 예시

```text
[PortPulse 아침 브리핑]

오늘 부산발 미주서안 KCCI는 2,340p로 전주 대비 7.8% 상승했습니다.
원/달러 환율은 1,380원으로 소폭 완화됐지만, 운임 상승분을 상쇄하기에는 부족합니다.

자동차 부품 1차 선적은 예산 $2,800/FEU 대비 약 18% 초과 가능성이 있습니다.
8월 3주차 선적 예정이라면 2주 내 부킹 확정을 우선 검토하세요.

근거: KCCI, SCFI, ECOS, 주요 해운 뉴스
```

### 시스템 처리

```text
EventBridge Scheduler
→ Market Ingest Lambda
→ 외부 데이터 API/뉴스 수집
→ Raw Data S3 저장
→ Aurora PostgreSQL 저장
→ Risk Lambda 실행
→ Bedrock Briefing 생성
→ Alert Lambda 발송
```

### 성공 상태

사용자는 매일 다음 내용을 받는다.

- 오늘의 운임 변화
- 환율/거시 지표 변화
- 주요 운임 영향 뉴스
- 내 선적 중 주의해야 할 건
- 오늘 해야 할 행동

### 실패/예외 상태

| 상황 | 처리 |
| --- | --- |
| 일부 데이터 수집 실패 | 마지막 정상 데이터와 실패 출처 표시 |
| 뉴스 수집 실패 | 수치 데이터 중심 브리핑 발송 |
| Bedrock 호출 실패 | 룰 기반 요약 템플릿으로 대체 |
| 알림 발송 실패 | 대시보드에 미발송 상태 표시 |

## 3. 위험 선적 발생 시 알림 플로우

### 목적

등록된 선적 건이 예산 초과, 납기 부족, 운임 급등, 이벤트 리스크 조건에 걸리면 사용자가 접속하지 않아도 즉시 경보를 받는다.

### 사용자 상황

사용자는 모든 선적 건을 매일 직접 확인하기 어렵다. PortPulse는 위험 조건이 일정 기준을 넘을 때만 강한 알림을 보내 사용자의 행동을 유도한다.

### 플로우

```text
시장 데이터 업데이트 또는 선적 정보 변경
→ 선적별 리스크 재계산
→ 위험 기준 초과 여부 확인
→ 예산 초과 금액 계산
→ 부킹 타이밍 추천 생성
→ Bedrock이 알림 문구 생성
→ 알림 채널 확인
→ 텔레그램/카카오톡/이메일 발송
→ 사용자가 알림 클릭
→ 상세 리스크 화면 진입
→ AI에게 근거 질문
→ 부킹 확정/대기/물량 조정 결정
```

### 알림 발생 조건

| 조건 | 예시 | 알림 강도 |
| --- | --- | --- |
| 예산 초과율 높음 | 예산 대비 예상 +15% 이상 | 높음 |
| 초과 비용 큼 | 월 물량 기준 $2,000 이상 초과 | 높음 |
| 선적 예정일 임박 | 선적 예정까지 2주 이하 | 높음 |
| 견적 유효기간 임박 | 유효기간 3일 이하 | 중간 |
| 운임 단기 급등 | KCCI 전주 대비 +7% 이상 | 중간 |
| 이벤트 리스크 | 홍해, 파업, 항만 혼잡 | 중간 |
| 납기 여유 부족 | ETA와 납기일 차이 5일 이하 | 높음 |

### 알림 메시지 예시

```text
[PortPulse 위험 선적 경보]

자동차 부품 1차 / 부산 → 미주서안 / 8월 3주차 선적

위험도: HIGH
예산 $2,800/FEU 대비 예상 운임이 약 18% 높습니다.
월 4 FEU 기준 약 $2,016 초과 가능성이 있습니다.

추천:
2주 내 부킹 확정 또는 일부 물량 선적 시점 앞당기기를 검토하세요.

근거:
KCCI 단기 상승, SCFI 보조 상승, 항만 혼잡 뉴스, 견적 유효기간 임박
```

### 상세 화면에서의 사용자 행동

| 사용자 행동 | 시스템 반응 |
| --- | --- |
| 알림 클릭 | 해당 선적 상세 화면으로 이동 |
| 근거 보기 | KCCI/SCFI/환율/뉴스 근거 표시 |
| AI에게 질문 | Bedrock이 선적 맥락 기반 답변 |
| 부킹 확정 표시 | 선적 상태를 BOOKED로 변경 |
| 대기 선택 | 다음 브리핑에서 계속 추적 |
| 알림 끄기 | 해당 선적 또는 항로 알림 제외 |

### 시스템 처리

```text
Risk Lambda
→ 위험 점수 계산
→ risk_results 저장
→ 경보 기준 확인
→ Bedrock 알림 문구 생성
→ Alert Lambda
→ Telegram/Kakao/Email 발송
→ 발송 로그 저장
```

### 성공 상태

사용자는 위험 선적에 대해 다음을 빠르게 판단할 수 있다.

- 왜 위험한지
- 얼마가 초과될 수 있는지
- 지금 부킹해야 하는지
- 어떤 근거 데이터가 있는지
- 어떤 행동을 해야 하는지

### 실패/예외 상태

| 상황 | 처리 |
| --- | --- |
| 알림 채널 미설정 | 대시보드 내 경고만 표시 |
| 알림 발송 실패 | 재시도 후 실패 로그 저장 |
| 위험 근거 부족 | "데이터 부족" 상태로 표시하고 무리한 추천 금지 |
| 사용자가 부킹 완료 처리 | 이후 해당 선적의 부킹 타이밍 알림 중단 |

## 전체 유저 경험 요약

```text
최초 1회:
선적 정보와 예산 기준을 등록한다.

매일:
PortPulse가 시장 데이터를 수집하고 내 선적 건을 다시 판단한다.

위험 발생 시:
사용자는 접속하지 않아도 부킹 타이밍 경보를 받는다.

최종 행동:
사용자는 포워더 견적을 수동 수용하는 대신,
예산·납기·시장 근거를 보고 부킹 시점을 결정한다.
```

## MVP 우선순위

### 1차 MVP에 반드시 포함

- 선적 정보 등록
- 기준 예산단가 입력
- 물량 입력
- KCCI/SCFI/환율/뉴스 샘플 데이터
- 리스크 점수 계산
- 부킹 타이밍 추천 문구
- Bedrock 기반 설명
- 텔레그램 알림

### 1차 MVP에서 단순화 가능

- Cognito 로그인은 데모 사용자로 대체 가능
- 실제 KCCI/SCFI API는 샘플 데이터로 대체 가능
- 카카오톡 알림은 텔레그램으로 대체 가능
- Bedrock 멀티에이전트는 단일 Bedrock 호출로 대체 가능
- Aurora는 로컬 PostgreSQL 또는 JSON 샘플로 대체 가능

### 발표에서 확장 구조로 설명

- Cognito 회사별 인증
- S3 업로드 파일 파싱
- EventBridge 매일 배치
- Aurora PostgreSQL 결합 허브
- Bedrock Agent Action Group
- 뉴스/운임/거시 분석 Sub-agent
- 카카오 알림톡 연동
